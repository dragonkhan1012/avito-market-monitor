# Архитектура

## Пользовательский сценарий

`avito.py` принимает команду или открывает меню из `menu.py`. Ссылка преобразуется в параметры поиска модулем `link_resolver.py`; настройки сохраняются в JSON отдельно от объявлений.

Для профиля товаров `market_monitor.Monitor` получает страницы через `avito_client.CalmClient`, записывает наблюдения в `MarketStore`, организует чтение описаний, анализ и выгрузку. Первая страница дополнительно обновляется между глубокими страницами.

## Основные модули

| Файл | Ответственность |
| --- | --- |
| `avito.py` | Команды `add`, `list`, `scan`, `watch`, `table`, `telegram`; настройки поисков |
| `menu.py` | Интерактивный интерфейс терминала |
| `link_resolver.py` | Преобразование ссылки, категории и города в параметры запроса |
| `avito_client.py` | HTTP-сессия, получение страниц и обработка транспортных ошибок |
| `market_monitor.py` | Цикл сбора, дочитывание описаний, анализ и Excel-отчёт |
| `market_store.py` | SQLite, история цен, прогресс, состояния описаний и очередь уведомлений |
| `product_identity.py` | Нормализация характеристик MacBook/iPhone и проверка совпадения с запросом |
| `goods.py` | Представление товара, правила сравнения, таблицы Excel |
| `listing_details.py`, `item_page.py` | Извлечение описания и сведений со страницы объявления |
| `profiles.py`, `apartments.py` | Разделение сценариев товаров и недвижимости |
| `telegram_notify.py` | Настройки бота, сообщения и обработка ошибок Telegram |
| `telegram_browser.py` | Команды и кнопки просмотра предложений по локальной базе |
| `process_lock.py` | Защита поиска от одновременного изменения несколькими процессами |

## Хранение

SQLite — рабочий источник для мониторинга товаров. История объявлений не удаляется при пропаже предложения из выдачи. Отдельные состояния позволяют повторять неудавшиеся операции и продолжать обход после остановки.

Существующие JSON-данные импортируются в SQLite; совместимые JSON-копии обновляются. Уведомления хранятся в очереди и помечаются после отправки. При аварии между отправкой и записью подтверждения возможно повторное сообщение.

Excel сначала записывается во временный файл. Ошибка замены открытой книги не должна уничтожать сохранённую базу.

## Граница анализа

Определение товара не является универсальной классификацией всех категорий. Для неполных, противоречивых или неподдерживаемых характеристик сохраняется причина, по которой автоматическая оценка не выдана.

Цена сравнивается с объявлениями, а не с реальными завершёнными сделками. Правила и ограничения подробно описаны в [MONITORING.md](../MONITORING.md).

## Исследовательские модули

`main.py`, `firewallpow_payload_reference.py`, `qrator_payload_codec.py` и вспомогательные `trace_*`, `extract_*`, `probe_*`, `analyze_*` относятся к низкоуровневой работе с протоколом и диагностике. Основной клиент использует часть общих функций `main.py`; это ещё не полностью изолированный слой.

Сторонний каталог `GeekedTest/` сохранён с собственной лицензией. Дополнительная группа зависимостей `captcha` нужна для отдельного старого сценария. Захваченные бандлы сайта и браузерные трассировки в Git не включены; диагностические скрипты, которым они нужны, требуют локальных входных файлов.

## Проверки

Тесты бизнес-логики подменяют клиент и Telegram, используют временные базы и искусственные объявления. `test_fixtures/codec-vectors.json` содержит синтетические фиксированные векторы кодека. Live-проверка в `acceptance_test.py` не входит в обычный запуск pytest.
